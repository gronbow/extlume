# 兼容性与故障排查

## 适用场景

本应用面向 Windows 10/11 中处于活动状态的物理外接显示器，尤其适合 Windows 只给笔记本内置屏提供亮度滑块、而外接屏 OSD 又无法使用的情况。

“支持”分为两层：

1. 完整连接链路能够透传 DDC/CI 时，调节**硬件背光**；
2. DDC/CI 不可用、Windows 能够安全识别物理外接屏，且该屏不与内置屏共用桌面源时，使用**软件调暗**。

每张显示器卡片都会明确显示当前模式。

## 连接方式参考

| 连接方式 | 硬件 DDC/CI 预期 | 回退方式 |
|---|---|---|
| 直连 HDMI / DisplayPort | 通常支持 | 软件调暗 |
| USB-C DP Alt Mode | 通常支持，取决于设备 | 软件调暗 |
| 雷电 / USB-C 扩展坞 | 取决于扩展坞固件与拓扑 | 软件调暗 |
| DisplayLink / 间接有线适配器 | 取决于驱动 | 软件调暗 |
| KVM / 主动转接器 | 经常阻断 DDC/CI | 软件调暗 |
| VGA / DVI 转换链路 | 差异很大 | 软件调暗 |
| Miracast | 没有物理 DDC/CI 链路 | 能安全分类时使用软件调暗 |
| 远程或虚拟显示器 | 主动排除 | 无 |

## 型号识别过程

1. Windows DisplayConfig 提供活动显示源与目标；
2. 优先使用 EDID 友好名称；
3. WMI 元数据和硬件型号代码作为回退；
4. 通过输出技术识别并排除嵌入式内置屏；
5. 排除虚拟显示器；
6. 只为精确匹配的 Windows 显示源枚举 DDC/CI 句柄。

复制显示时，应用优先用物理显示器描述匹配 EDID 型号；没有名称但两侧数量一致时才按位置映射。数量不一致又无法确认时会拒绝猜测。

笔记本内置屏参与“复制”时，应用仍会尝试外接屏硬件 DDC/CI，但物理句柄必须与外接屏 EDID 型号唯一匹配，不允许按位置猜测。若硬件调光不可用，软件遮罩会被主动阻止，因为共享桌面源会让遮罩同时调暗内置屏。切换到“扩展”并重新扫描后，才会启用安全的软件回退。

## 硬件调光失败的常见原因

- 显示器 OSD 中关闭了 DDC/CI；
- 显示器没有实现亮度 VCP `0x10`；
- 线缆、转接器、扩展坞、KVM 或 MST Hub 不透传 DDC/CI；
- 显卡驱动或其他厂商软件拦截显示器控制；
- 显示器返回了错误的能力或亮度范围；
- 睡眠、热插拔或换接口后拓扑发生变化；
- 显示器固件调用卡住并触发超时。

应用先尝试 Windows 高级亮度接口，再读取标准 VCP `0x10`，不会发送任意 VCP 指令。微软也明确说明，许多显示器没有完整实现 MCCS/DDC/CI，因此低级控制行为取决于硬件：
[SetVCPFeature 文档](https://learn.microsoft.com/windows/win32/api/lowlevelmonitorconfigurationapi/nf-lowlevelmonitorconfigurationapi-setvcpfeature)。

## 排查步骤

1. 确认外接屏已在 Windows 显示设置中启用；
2. 点击“重新扫描”；
3. 能操作 OSD 时，确认 DDC/CI 已开启；
4. 尽量绕过扩展坞、KVM 或转接器进行直连测试；
5. 更新显卡驱动、扩展坞固件；
6. 暂时退出其他显示器控制软件；
7. 运行只读的 `probe.cmd`，将脱敏输出附到兼容性 Issue。

## 软件调暗的限制

- 只降低感知亮度，不改变背光或功耗；
- 最低档仍保留可见画面，避免完全黑屏后无法恢复；
- 外接屏与内置屏共用复制桌面源时，软件遮罩会被阻止；
- 仅由外接屏组成、且共用一个桌面源的显示组会共用一个遮罩；
- HDR 和色彩管理内容在黑色遮罩下可能呈现不同观感；
- 退出应用会立即移除遮罩。
