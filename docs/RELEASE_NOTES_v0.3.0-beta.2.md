# ExtLume v0.3.0-beta.2

This hotfix corrects the high-DPI rendering regression in
`v0.3.0-beta.1`. Brightness-control behavior and the external-display safety
model are unchanged.

## Fixed

- Chinese and English text no longer clips or overlaps at 125%–200% Windows
  scaling.
- Brightness percentages retain the `%` sign.
- The Rescan button, mode badge, monitor name, note, slider, and state text
  remain inside their intended surfaces.
- The rounded Rescan button no longer leaves a rectangular black paint area.
- Moving ExtLume between monitors using different scaling settings now resizes
  geometry, fonts, rounded corners, and slider metrics together.
- Refreshing the monitor list now performs one buffered relayout and complete
  repaint, preventing stale controls from appearing in the header.

## Validation highlights

- Real-screen Chinese and English review on a 200% primary display.
- Live 200% → 100% → 200% mixed-DPI round trip.
- Read-only detection of the exact external `H25T7-3` hardware target.
- Slider-to-DDC/CI test with independent readback and restoration of the
  original brightness.
- Automated build, safety audit, DPI regression test, CI, and CodeQL.

## Beta limits

Real hardware validation covers one `H25T7-3` HDMI monitor through the Windows
high-level hardware-brightness API. Other monitor, dock, KVM, DisplayLink, MST,
and direct-VCP combinations remain community beta-matrix items.
